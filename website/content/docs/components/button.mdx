## Usage

```tsx
import { Button } from "vic-ui/ui"
```

```tsx
<Button variant="outline">Button</Button>
```

## Shapes

Use `square round` for a native circular icon button, or `size="icon" round` with the composable API. `round` on a text button makes a pill. Without `round`, buttons use the `--radius-button` token; compact toolbar and file controls use their smaller contextual radius.

The face follows the outer corner minus the border and padding inset: 2px for filled and outlined buttons, 0px for quiet and link buttons. The same geometry applies on hover and press, including accent buttons. Consumers need no radius overrides.

## One ink button per page

The ink look is a page's one committing action. In a development build, when a second `look="ink"` Button mounts inside the same `main` landmark, the console warns once, naming both buttons by their words. Buttons in a dialog or a popover are their own surface and are not counted. For the rare page that needs two, pass `allowSecond` to the one that must stay ink. A production build says nothing.

The composable `Button` from `vic-ui/ui` draws through the same button: `variant="default"` (its default) and `variant="destructive"` are ink buttons and are counted, and it takes `allowSecond` as well.

```tsx
<main>
  <Button>Publish</Button>
  <Button look="line">Save the draft</Button>
  <Button allowSecond>Publish and notify</Button>
</main>
```

## Custom accent

Both APIs support `tone="accent"` on a filled button: `Button` from `vic-ui` uses `look="ink"`; `Button` from `vic-ui/ui` uses `variant="default"`. `ButtonLink` and `buttonVariants({ tone: "accent" })` support the same treatment. The live Custom accent example above compares both APIs in both themes, including higher-contrast colors.

```css
.brand-actions {
  --button-accent: light-dark(oklch(.5 .075 240), oklch(.74 .075 240));
  --button-on-accent: light-dark(oklch(.97 0 0), oklch(.205 0 0));
}
```

```tsx
<div className="brand-actions">
  <Button tone="accent">Check and save</Button>
</div>
```

Set both tokens on the button or an ancestor. `--button-accent` is the base color; `--button-on-accent` is the explicit text and spinner color. Vic derives the edge, rim and distinct face stops for rest, hover and press. Choose a foreground with sufficient contrast against all face states; arbitrary color pairs are not automatically corrected. The example's five hues are tested at 4.5:1 or greater in every enabled state.

Without `tone="accent"`, the monochrome treatment stays unchanged. Outline, secondary, quiet and link looks keep their existing appearance. Danger, caution and the composable destructive variant take precedence over the accent. Busy, disabled and keyboard focus behavior stay the same.

For a consumer that already has theme tokens, map `--button-accent: var(--ph-accent)` and `--button-on-accent: var(--ph-ink-inverse)`, then use `tone={customAccent ? "accent" : undefined}` on its primary Button wrapper. Remove overrides of `--ink-face-*`, `--ink-rim-*` and `--ink-words`; supplying identical face stops bypasses the texture. No separate hover token is needed.

## Root Button: compact and glass looks

```tsx
import { Button, ButtonLink } from "vic-ui";

<Button look="line" size="xs">Edit</Button>
<Button look="glass">Open details</Button>
<ButtonLink to="/reports" look="line" size="xs">Reports</ButtonLink>
```

The root API supports `look="ink"|"line"|"glass"|"quiet"|"link"` and `size="xs"|"md"|"lg"`. Its default remains the textured ink button. Glass and compact sizing are explicit options; they do not replace existing defaults or the accent contract above. `disabledReason` is combined with a supplied `aria-describedby`, preserving host descriptions.
