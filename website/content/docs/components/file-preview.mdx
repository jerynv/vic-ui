## Usage

These components are exported from `vic-ui`. Load `vic-ui/styles.css`, or use the existing `vic-ui/ui/styles.css` entry if your application already imports it. Both include the preview styles; there is no separate stylesheet or provider.

```tsx
import { Button, FilePreviewStage, TextPreview } from "vic-ui";
import "vic-ui/styles.css";

function ReadmePreview({ input, onDownload }: {
  input: Blob;
  onDownload: () => void;
}) {
  return (
    <FilePreviewStage
      file={{ id: "readme-v1", name: "readme.txt", size: input.size }}
      actions={<Button look="line" onClick={onDownload}>Download</Button>}
    >
      <TextPreview input={input} name="readme.txt" />
    </FilePreviewStage>
  );
}
```

The examples above use local synthetic files. Their download links contain those exact sample contents. In an application, the host supplies its own download action and decides whether it is available.

## What is included

| Component | Purpose |
| --- | --- |
| `FilePreviewStage` | File name, optional size and description, toolbar, actions and preview body. |
| `FilePreviewToolbar` | A named, wrapping group for existing Vic controls. |
| `FilePreviewStatus` | Loading, error and unsupported states, with optional retry and host actions. |
| `FilePreviewDialog` | Full-screen native dialog with file navigation, Escape to close and focus return. |
| `ImagePreview` | Browser-decodable local images with zoom, pan and fit controls. |
| `TextPreview` | Bounded UTF-8 text with line numbers and a truncation notice. |
| `DelimitedPreview` | Bounded CSV or TSV in a scrollable table. |

Optional subpaths add DOCX, stored XLSX cells, extracted PPTX text and native audio/video. PDF and Markdown renderers are not included. Text that contains markup remains text. The host chooses the renderer; there is no automatic classification or file conversion.

## Supply stable local input

Each renderer takes `input: Blob | Uint8Array<ArrayBuffer>`. It does not accept a remote URL or fetch file bytes. Keep the input identity stable across unrelated renders, and replace it when the file's contents change.

```tsx
const input = useMemo(
  () => new Blob(["A local sample\n"], { type: "text/plain" }),
  [],
);

<TextPreview input={input} name="sample.txt" />
```

For real files, keep the loaded Blob or byte array in the host's loader state. Do not construct a new Blob inline on every render or mutate a supplied byte array in place. When a changed file should reset the renderer's view, key it by the file identity and version:

```tsx
<TextPreview key={`${file.id}:${file.version}`} input={input} name={file.name} />
```

Dialog item IDs should also include the version when replacing content under the same file name.

The host owns permission checks, loading, cancellation and stale-result handling. Mount a renderer only with the bytes that belong to the current selection; use `FilePreviewStatus` while the host is loading or cannot provide them.

## Images

```tsx
<ImagePreview input={imageBlob} alt="Floor plan of the shared workspace" />

<ImagePreview
  input={pngBytes}
  mimeType="image/png"
  alt="Floor plan of the shared workspace"
  onError={reportPreviewError}
/>
```

`alt` is required. A Blob carries its own MIME type; `mimeType` applies to byte arrays and defaults to `image/png`. The image is displayed in an `img` element, including SVG; SVG markup is never inserted into the document.

Image input is limited to 20 MiB of encoded bytes before a copy or object URL is created. `maxBytes` can lower that limit. This bounds the encoded input, not the browser decoder's pixel memory; the host still decides which image sizes and formats to accept.

The viewer provides zoom in, zoom out and fit controls. Pointer dragging pans a zoomed image. Double-click or double-tap toggles zoom; touch supports pinch. With the image area focused, `+` and `-` zoom, `0` fits, and vertical arrow or Page Up/Down keys pan a zoomed image. Browser decoding determines which image formats can be displayed.

## Text and delimited data

```tsx
<TextPreview input={textBlob} name="readme.txt" maxLines={500} />

<DelimitedPreview
  input={tableBlob}
  name="measurements.tsv"
  delimiter={"\t"}
  maxRows={250}
  maxColumns={20}
/>
```

`DelimitedPreview` uses a comma by default; `delimiter={"\t"}` selects TSV. Quoted fields can contain delimiters, escaped quotes and line breaks. Cell contents remain text, including values that look like spreadsheet formulas.

| Renderer | Default byte budget | Default output budget |
| --- | --- | --- |
| `ImagePreview` | 20 MiB | Zoom from fit to 8 times the fitted size |
| `TextPreview` | 512 KiB | 20,000 lines |
| `DelimitedPreview` | 1 MiB | 1,000 total rows, including the header, and 60 columns |

`maxBytes`, `maxLines`, `maxRows` and `maxColumns` can lower the corresponding budget; they cannot raise the library limits. A partial preview identifies truncation. Download remains a host action for accessing the original file.

All three renderers accept `className` and `onError(error: Error)`. `name` supplies an accessible file name for text and table previews. These are preview components, not document editors.

## Optional Office and media previews

These entries use the same ready-input boundary and shared styles. They are separate from the root bundle and do not load a renderer until your application imports it.

```tsx
import { AudioPreview, VideoPreview } from "vic-ui/preview/media";
import { XlsxPreview, PptxPreview } from "vic-ui/preview/office";

<AudioPreview input={audioBlob} title="Interview recording" />
<VideoPreview input={videoBytes} mimeType="video/webm" title="Product walkthrough" />
<XlsxPreview input={workbookBlob} title="Quarterly measurements" maxRows={250} />
<PptxPreview input={slidesBlob} title="Planning presentation" maxSlides={20} />
```

All five optional components require `input` and an accessible `title`. They accept `className`, `maxBytes` and `onError(error: Error)`. Limits can be lowered, never raised. Conversion and decoding errors provide a local Try again control; it retries the supplied bytes, not the host's network request. Media size/type refusals require a different input instead of offering a retry.

`AudioPreview` and `VideoPreview` use native browser controls, metadata loading and no autoplay. `mimeType` can describe byte arrays; a Blob's own type is used when no override is supplied. Missing MIME metadata permits native decoding. Supported codecs depend on the browser. Each player is stopped and its library-created object URL revoked when replaced or unmounted. The host must permit `blob:` in its `media-src` policy. A 64 MiB encoded-input cap is checked before making a copy or URL; this does not bound the browser decoder's memory or recording duration. There is no streaming URL, transcoding or custom player API.

`XlsxPreview` displays stored cell values, worksheet tabs and row/column labels. Formula cached values remain text; formulas are not recalculated. Dates and number formatting are not reproduced. `maxRows`, `maxColumns` and `maxSheets` can reduce the displayed content, with a visible notice. Legacy `.xls` files are not supported.

`PptxPreview` displays slide text in presentation order, with an explicit extracted-text label. It does not reproduce slide design, pictures, animations or embedded media. `maxSlides` reduces the displayed slide count. Legacy `.ppt` files are not supported.

### DOCX

Install the optional renderer dependency only when using DOCX:

```sh
npm install docx-preview@0.4.1
```

Use a lazy import to keep the renderer out of the initial application path:

```tsx
import { lazy, Suspense } from "react";
import { FilePreviewStatus } from "vic-ui";

const DocxPreview = lazy(() => import("vic-ui/preview/docx").then(module => ({
  default: module.DocxPreview,
})));

<Suspense fallback={<FilePreviewStatus status="loading" message="Preparing document preview." />}>
  <DocxPreview input={documentBlob} title="Project brief" />
</Suspense>
```

DOCX uses `docx-preview` after checking and rebuilding the input archive. Rendering happens in an inert document; the sanitized result is shown in an empty-sandbox `srcdoc` iframe with a restrictive content policy. Hyperlinks are disabled. The frame fits its container and scrolls internally; resizing recreates its view. Host CSP must permit this frame and its embedded `data:` raster images. DOCX rendering is a preview, not an editing or Word-layout-fidelity contract.

Supported embedded images are bounded PNG and JPEG files, validated with `createImageBitmap`. Legacy VML, SVG drawings, embedded HTML, OLE objects, macros, external resources and unsupported images are refused. Embedded fonts, comments and tracked-change rendering are disabled. Legacy `.doc` files are not supported. Office archive decoding requires `DecompressionStream("deflate-raw")` for compressed entries; browsers without it receive an error instead of a partial success.

### Office budgets

Office input is rejected before parsing when a hard budget is exceeded. Lower display limits produce a labeled partial preview; they do not bypass parser budgets.

| Boundary | Hard limit |
| --- | --- |
| Every Office file | 10 MiB encoded, 512 ZIP entries, 8 MiB per expanded part, 32 MiB expanded total |
| Each XML part | 4 MiB, 100,000 elements, depth 128; DTDs and entities refused |
| XLSX parser | 32 worksheets, 50,000 stored cells, 20,000 shared strings, 1,000,000 characters each for shared strings and rendered cell text |
| XLSX displayed content | 1,000 rows and 60 columns per worksheet |
| PPTX parser | 100 slides, 10,000 paragraphs, 500,000 text characters |
| DOCX parser | 8 MiB total XML, 100,000 total elements, 1,000,000 text characters, 10,000 table cells |
| DOCX output | Conservative 100-page work bound, 50,000 nodes, 8,388,608 HTML code units, 524,288 style code units |
| DOCX relationships/numbering | 2,048 relationships; 128 numbering definitions, 256 instances, unique levels 0 through 8, 512 expanded levels, 8,192 characters per level and 262,144 weighted expanded characters |
| DOCX images | 100 PNG/JPEG files and placements, 2 MiB each and 4 MiB total encoded; 4 million pixels each and 8 million total, including repeated placements |

These bounds limit library work. They do not replace the host's file acceptance policy. Unsupported or encrypted archives, unsafe paths, inconsistent lengths, invalid CRCs and oversized expansion are refused. XLSX/PPTX individual text fragments are capped at 16,384 characters. DOCX table spans are capped at 100. The main part must be `word/document.xml`; relationship-selected parser parts must already have passed XML validation. Header, footer and note image work is checked using a conservative page/reference bound before conversion, so complex documents can be refused before reaching 100 actual pages. Downloading the original file remains a host action.

## Full-screen navigation

```tsx
const [activeId, setActiveId] = useState<string | null>(null);
const opener = useRef<HTMLButtonElement>(null);

<Button ref={opener} onClick={() => setActiveId("readme-v1")}>
  Open full screen
</Button>
<FilePreviewDialog
  items={[
    {
      id: "readme-v1",
      label: "readme.txt",
      content: <TextPreview input={textBlob} name="readme.txt" />,
    },
  ]}
  activeId={activeId}
  onActiveIdChange={setActiveId}
  returnFocusRef={opener}
  renderActions={() => <Button look="line" onClick={download}>Download</Button>}
/>
```

`activeId={null}` closes the dialog. Each item has a unique, stable `id`, a `label` and host-provided `content`. With multiple items, previous and next controls navigate the list. With focus on the dialog content container, left and right arrow keys navigate files. Embedded controls and scrollable renderers keep their own arrow keys. If changing items removes the focused content, focus returns to that container. Closing restores focus to `returnFocusRef`, or to the element that opened the dialog when no ref is supplied.

## Host-controlled states

```tsx
<FilePreviewStatus status="loading" message="Loading the selected file." />
<FilePreviewStatus
  status="error"
  message="The file could not be read. Try loading it again."
  onRetry={reloadSelectedFile}
/>
<FilePreviewStatus
  status="unsupported"
  message="This file type has no preview."
  actions={<Button look="line" onClick={download}>Download</Button>}
/>
```

Use `title` to override a state's default heading. `onRetry` adds a working Try again button whose callback belongs to the host; the status component does not start a request. The loading state exposes `aria-busy`, errors use an alert, and the preview body retains a reserved area for status content.

## Source and compatibility

The shared stage, full-screen boundary and image interactions were extracted from the verified V-Client source pin `2f2713d8744373455d6be2953af26f68ecb37f6f`, then adapted to Vic's existing controls and tokens. See the repository's third-party notices for provenance. Text and CSV parsing adapt the same pin's TextView and TableView implementations, with stricter input/output budgets and stale-read cleanup.

The core preview exports remain available at the root. Optional Office/media subpaths adapt the same verified source pin and preserve all 137 existing root exports. DOCX alone uses the optional dependency described above; existing components and the `vic-ui/ui` API remain available.
