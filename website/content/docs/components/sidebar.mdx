## Usage

```tsx showLineNumbers title="app/layout.tsx"
import { SidebarProvider, SidebarTrigger } from "vic-ui/ui"
import { AppSidebar } from "@/components/app-sidebar"

export default function Layout({ children }: { children: React.ReactNode }) {
  return (
    <SidebarProvider>
      <AppSidebar />
      <main>
        <SidebarTrigger />
        {children}
      </main>
    </SidebarProvider>
  )
}
```

```tsx showLineNumbers title="components/app-sidebar.tsx"
import {
  Sidebar,
  SidebarContent,
  SidebarFooter,
  SidebarGroup,
```

## Persistent controllers with the root Sidebar

This contract applies to `SidebarProvider` and `Sidebar` imported from **`vic-ui`**, the root API. Keep persistent observers and subscriptions as stable siblings of `Sidebar` inside the provider:

```tsx
import { Sidebar, SidebarProvider } from "vic-ui"

<SidebarProvider>
  <ConversationObservers />
  <Sidebar>presentation</Sidebar>
  <main />
</SidebarProvider>
```

`ConversationObservers` is host-owned application logic; the library does not implement or start subscriptions. It can use the root `useSidebar()` context and remains mounted while the provider remains mounted with stable child identity. Keep it outside any conditional branch that hides the presentation.

`Sidebar` children are **not persistent controllers**. The desktop `aside` becomes a mobile dialog at the breakpoint, and the closed mobile dialog unmounts its presentation. Closing and reopening can remount those children. Put durable data subscriptions, background observers and nonvisual state above the presentation or in the sibling slot shown here.

This separation preserves the mobile dialog's focus trap, background isolation, Escape/outside dismissal and return to its opener. The closed mobile presentation stays absent and unfocusable. `keepMounted` alone does not establish the sibling lifetime contract, and force-mounting hidden focusable presentation is not a substitute.

The source regression in `tests/controls-layout.test.mjs` asserts one observer mount and one active subscription through desktop collapse, mobile open/close and both breakpoint directions. It also checks closed presentation absence, tab order, focus trapping and focus return. No root Sidebar runtime change is needed for this composition.

## Root Sidebar current location

`SidebarMenuButton` from `vic-ui` emits `aria-current="page"` for its current item. An explicitly supplied `aria-current` takes precedence. Keep selection in the host and use the persistent-controller composition above for subscriptions.

## Root Sidebar options

These apply to the root API from **`vic-ui`**.

- **Density.** By default the rail follows the page's `data-density`: rows 2rem tall, 1.75rem under `compact` and 2.25rem under `comfortable`. `SidebarProvider` takes `size` to give the rail its own density whatever the page's: `size="sm"` sets every row 1.75rem tall and every group label a step smaller, and `size="md"` holds rows at 2rem and labels at their full size. A row's own `size="sm" | "md" | "lg"` (1.75rem, 2rem or 2.5rem) and a label's own `size` outrank both. The height is `--sidebar-row-height` on the provider.
- **Spacing between groups.** Groups after the first sit 0.75rem apart while the rail is open, the room a folded rail's rule takes. Set `--sidebar-group-gap` on the provider to change it, or `0` for none.
- **Counts.** `SidebarMenuButton` takes `count={{ value, label, tone? }}`: a soft pill at the row's end while open, the dot on the mark while folded. `label` is what a screen reader hears, once. `Count` and `Badge` both take `soft`, the tone's ink on its tint.
- **A toggle.** `SidebarTrigger` is a quiet square button with the rail's mark that calls `toggleSidebar`. It is named for what it will do ("Collapse menu", "Expand menu") and `aria-expanded` says the state. Put it in the rail's `SidebarHeader` after the brand: it sits at the header's end, and folded the header shows only the trigger, over the marks. On a phone it draws nothing inside the sheet, which has its own close, so put one in the page's header there too.
- **Weight.** Rows, labels and counts use `--weight-quiet`, which follows `--weight-ui` (500). Set either to 400 in your theme stylesheet for a lighter interface. The current row is told by its fill and icon, never by weight.

```tsx
import { Sidebar, SidebarContent, SidebarGroup, SidebarGroupLabel, SidebarHeader, SidebarMenu, SidebarMenuButton, SidebarProvider, SidebarTrigger, useSidebar } from "vic-ui"
import { ChatsCircleIcon } from "vic-ui/icons"

function PageHeader() {
  const { isMobile } = useSidebar()
  return <header>{isMobile ? <SidebarTrigger /> : null}</header>
}

<SidebarProvider size="sm">
  <Sidebar aria-label="Admin">
    <SidebarHeader>
      <Brand />
      <SidebarTrigger />
    </SidebarHeader>
    <SidebarContent>
      <SidebarGroup>
        <SidebarGroupLabel>Work</SidebarGroupLabel>
        <SidebarMenu>
          <SidebarMenuButton href="/chat" icon={<ChatsCircleIcon size={16} />} tooltip="Chat" count={{ value: 4, label: "4 mentions" }}>
            Chat
          </SidebarMenuButton>
        </SidebarMenu>
      </SidebarGroup>
    </SidebarContent>
  </Sidebar>
  <main>
    <PageHeader />
  </main>
</SidebarProvider>
```

```css
/* theme.css, imported after vic-ui's stylesheet, outside any @layer */
:root { --weight-quiet: 400; }
```
